# 项目章程（PROJECT_CHARTER）

> 本文件是项目控制面的顶层文件。任何阶段顺序或验收制度的变更必须通过 ADR 记录并经用户确认。

## 项目名称

航天知识助手（Aerospace Knowledge Assistant）——基于真实航天资料的证据型知识助手。

## 项目目标

构建一个以原始资料为唯一证据来源的知识助手系统，能够：

1. 解析并规范化多格式航天资料（文档、表格、图文等）；
2. 通过 Hybrid RAG 与 GraphRAG 检索证据；
3. 基于工程追溯图回答带完整引用的问题；
4. 生成并增量维护带引用的 LLM Wiki；
5. 管理用户、任务和工作经验的 Agent Memory；
6. 建立可持续的评测、可观测性和部署体系。

核心原则：**最终答案必须回到原始证据（Source / Evidence / Provenance），LLM 生成内容永远不是 ground truth。**

## 目标用户

- 航天工程领域的工程师和研究人员（需要快速、可靠、可追溯的资料查询）；
- 项目学习者本人（通过构建该系统系统性地掌握 RAG、GraphRAG、Memory 与评测工程）。

## 第一版目标任务

交付一个可本地运行的端到端系统，能够：

- 接收一个自然语言问题；
- 在已登记的资料范围内检索证据；
- 返回带 source_id 引用的回答，并标注不可回答 / 证据不足的情况；
- 对每类问题给出可复现的评测指标。

## 明确的非目标

- 不构建面向公众的在线服务；
- 不做多领域通用问答（仅限已登记航天资料范围）；
- 不追求在第一版中实现全部高级特性（多 Agent、GNN、自训练 Embedding 等）；
- 不把 LLM 输出直接写入知识库而不经人工或规则审核；
- 不在本项目中修改或再创作原始航天资料。

## 数据范围

- 待用户确认：具体的航天资料目录、格式清单和安全等级（见 CURRENT_STATUS.md 的阻塞项）；
- 资料一经登记进入 docs/reports 的资料清单后，范围变更需走 ADR；
- 原始资料本体不进入本仓库（见 DATA_GOVERNANCE.md）。

## 数据安全边界

- 禁止外发级资料不得发送到任何外部模型 API；
- 本项目 P00–P03 阶段不调用任何外部模型 API；
- 日志、评测集、报告中不得出现敏感资料正文；
- API Key、凭证、敏感路径不得提交到仓库；
- 所有派生数据（Chunk、索引、评测样本等）必须保留 source_id 以支持删除传播。

## 角色分工

| 角色 | 职责 |
|------|------|
| 用户 | 资料范围、领域判断、敏感信息决策、关键技术决策最终拍板 |
| Codex | 路线维护、任务拆分、数据模型与实验设计、验收 GLM 实现、维护 ADR 与阶段报告 |
| GLM | 按任务包编码、编写测试、运行验证命令、汇报实现与偏差 |

详见 WORKFLOW.md。

## 技术路线

按 ROADMAP.md 的阶段门推进：P00 治理 → P01 解析 → P02 Baseline RAG → P03 评测 → P04 高级 RAG → P05 GraphRAG → P06 Wiki → P07 Memory → P08 集成部署。各阶段技术选型在该阶段内通过 ADR 决定，阶段顺序和验收制度不可跳过。

## 第一版成功标准

1. 每个阶段通过 docs/phases 中定义的通过标准并留有阶段报告；
2. 系统对可验证问题集合达到路线中设定的评测指标（具体阈值在 P03 定基线后确定）；
3. 每个回答均可追溯到原始资料的 source_id 与位置；
4. 不可回答 / 证据不足的问题被显式拒绝而非编造答案；
5. 全程无敏感资料外泄事件。

## 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 资料范围或安全等级迟迟未确认 | P00 无法通过 | 尽早向用户提交确认清单 |
| 原始资料格式复杂、解析质量不足 | 检索与引用错位 | P01 设解析质量门槛，未达标不进入 P02 |
| LLM 幻觉混入 Wiki 或答案 | 知识库污染 | 强制 Evidence 回链 + 人工审核门 |
| 依赖/成本失控 | 项目烂尾 | 每阶段 ADR 记录选型，优先复用 |
| 敏感信息进入日志或仓库 | 安全事故 | DATA_GOVERNANCE 约束 + 阶段检查项 |

## 当前假设

1. 用户拥有合法使用权的目标航天资料，并将在 P00 内确认范围与等级；
2. 全流程可在本地环境完成训练/推理以外的部分；
3. 各阶段可在不引入重型第三方依赖的前提下完成（确需引入时走 ADR）；
4. 用户能定期参与决策（资料分级、问题价值判断、验收抽查）。

## 需要用户后续确认的事项

1. 航天资料的具体目录、格式与数量；
2. 每份资料的安全等级（公开 / 内部可用 / 受限 / 禁止外发）；
3. 第一版优先服务的问题类型（工程参数查询 / 跨文档追溯 / 综述生成）；
4. 可用于本地运行的计算资源（是否有 GPU、可用显存）；
5. 哪些外部模型 API（若有）被允许、允许传输什么等级的内容。
