# P01 解析路由设计（parser routing）

> TASK-P01-001 产物。设计文档，不含实现。路由触发判定全部可用**结构信号**（字符数/文本层/图像覆盖率/zip 条目名/sheet 形态）廉价获得。

## 路由总览

```
文件 → 垃圾过滤(~$锁文件) → 格式分流
  ├─ PDF  → 页级双信号分类(文本量+图像覆盖率): R1 数字版 / R2 混合版 / R3 扫描版(OCR)
  ├─ DOCX → zip 条目检查 → R4 标准版 / R5 WPS 反斜杠版(先修复)
  ├─ DOC  → R6 (LibreOffice 转 docx 后走 R4)
  ├─ XLSX → zip 条目检查 + sheet 形态 → R7 常规 / R8 复杂多区
  └─ 其他 → R9 拒收（登记不解析）
```

## 页级分类：文字页 / 扫描页 / 插图 / 空页（PDF 路由的前置判定）

双信号：**文本字符数** + **最大图像覆盖率**（fitz 取页内最大 image bbox 面积 / 页面面积）。

| chars/页 | 最大图覆盖率 | 判定 | 处理 |
|----------|--------------|------|------|
| ≥ 50 | 任意 | 文字页；图 = 插图（bbox 局部、旁有文字） | 走文本提取；插图登记 `figure` 占位（图表内容属"暂不自动抽取"清单，首版不 OCR 单图） |
| < 50 | ≥ 85%（通常 1 张整页图） | 扫描页 | 走 OCR |
| < 50 | < 85% 且无大图 | 空页/装饰页 | 记 `page_omitted`，不产出 Element |

依据：插图是"页有文字、图是局部"；扫描页是"页无文字、图是全部"。实测吻合：签署纪要 8 文字页+1 扫描页（签署页整页图）；说明书 22 页文字 + 43 张局部插图；记录表 8 页全是整页图。

## R1 数字版 PDF

| 项 | 内容 |
|----|------|
| 触发 | 全部页判定为文字页 |
| 解析 | PyMuPDF 文本提取（保物理页号）；pdfplumber 检表格 |
| extraction_mode | `text_native` |
| 位置字段 | source_id + PDF 物理页号（PDF 无页码文本）+ 章节链（书签/字号推断） |
| 失败状态 | 提取异常→FAILED；chars/页 50~200 存疑→PENDING_REVIEW |
| 进索引 | 是 |
| 质量检查 | Q1 全套（见 P01-quality-requirements.md） |

## R2 混合版 PDF（文字页 + 扫描页）

| 项 | 内容 |
|----|------|
| 触发 | 部分文字页 + 部分扫描页 |
| 解析 | 文字页走 R1；扫描页走 R3 的 OCR，**页级处理**。例外：扫描页为签字/盖章页（位于文末、含签名栏特征）可标 `page_omitted=signature` 免 OCR——是否豁免首份人工标定 |
| extraction_mode | `text_native` + `text_ocr`（按页标注） |
| 位置字段 | 同 R1 + 每页 mode |
| 失败状态 | 页级降级，不整文件失败；OCR 页质量不过→该页 PENDING_REVIEW |
| 进索引 | 文字页进；OCR 合格页进；豁免/失败页不进 |
| 质量检查 | 扫描页占比记录；扫描页占比 > 50% → 整文件改判 R3 |

## R3 扫描版 PDF（纯扫描，OCR）

**P01 范围内处理**（P00 暂缓不等于 P01 暂缓；MinerU env 本机已备，Memory 项目实测 ~2.4s/页，330MB 级 8 页文档分钟级完成）。

| 项 | 内容 |
|----|------|
| 触发 | 全部/绝大多数页为扫描页（实测样本：记录表 8/8 页、全文文本层仅 7 字符） |
| 预处理 | 无（MinerU 自带 hybrid：文字直提+OCR+跨页表格合并） |
| 解析 | **MinerU**（独立 conda env 子进程调用，Memory 项目 extract.py 的调用方式已验证）→ markdown + 版面结构 |
| extraction_mode | `text_ocr` |
| 位置字段 | source_id + 物理页号 + OCR 版面块序号；MinerU 输出的表格单列 Table Element |
| 失败状态 | MinerU 超时/崩溃→FAILED；质量门不过→PENDING_REVIEW（**不是FAILED**——OCR 半成品仍有价值，人工接手） |
| 进索引 | 仅质量门通过的页/块 |
| 质量检查（OCR 专属，见下节） | OCR 不能只看"生成了文字" |
| 人工复核 | 3 份记录表全量人工比对（OCR 数字化的验收对象）；三份近重复副本 OCR 后互相比对（既验 OCR 又验主副本判同） |

**OCR 质量门**（为什么不能只检查"是否生成了文字"）：
1. cjk_ratio ≥ 0.2（中文资料 OCR 成乱码拉丁文的典型症状）；
2. 乱码字符率（\ufffd 及非预期码位）< 1%；
3. 每页字符密度与图幅复杂度一致性（整页表格页产出 < 50 字符 → 漏识）；
4. 表格块行列数守恒（MinerU 表格行数 vs 版面线框数）；
5. 关键字段抽检：编号类（SCS-01/Z0102 型）在 OCR 文本中可正则命中（印章/签字区允许缺失）。

## R4/R5 DOCX（同一路由，前置修复不同）

| 项 | 内容 |
|----|------|
| 触发 | .docx；R4=zip 条目正常，R5=条目含 `\`（WPS，本批全命中） |
| 预处理 | R5 先**临时副本重写条目名**（已验证修法，原始文件不动）——**在管线第一站统一解决，不在各解析器散修** |
| 解析 | python-docx：段落（标题样式层级）+ 表格（行×列，首行表头）+ 内嵌图占位 |
| extraction_mode | `docx_structured` |
| 位置字段 | source_id + 章节链（H1/H2/H3）+ 表格序号/行号 + 段落序 |
| 输出 | 段落 Element + 表格 Element（每行携带表头） |
| 失败状态 | zip 损坏→FAILED；修复后仍失败→FAILED 附原始错误 |
| 进索引 | 是 |
| 质量检查 | 标题层级非空率；表格行列守恒；文本量 vs 前次运行漂移告警 |

## R6 DOC（旧二进制）

| 项 | 内容 |
|----|------|
| 触发 | .doc |
| 解析 | LibreOffice headless **→ docx 后走 R4 路由**（保表格结构；直接转 txt 会丢结构）。转换失败才降级 txt |
| extraction_mode | `doc_converted`（记录转换链） |
| 失败状态 | LibreOffice 失败→FAILED。**禁用 antiword 直出兜底**（实测 cjk_ratio 0.06 丢中文——宁可 FAILED 也不产出静默丢内容的"成功"） |
| 质量检查 | 转换后 cjk_ratio ≥ 0.2；2 份 .doc 全量人工核对（履历书，量小） |

## R7/R8 XLSX（同一路由，复杂度分流）

| 项 | 内容 |
|----|------|
| 触发 | .xlsx；R7=无合并/单逻辑区/无多行表头；R8=合并单元格、多行表头（首行含空且列>2）、多关联 sheet、公式（本批以 R8 为主） |
| 预处理 | 同 R5 的 WPS 修复 |
| 解析 | openpyxl：按 **sheet + 逻辑区域**切分（表头行→空行/汇总行）；公式 data_only 求值，求不到保留原式 |
| extraction_mode | `xlsx_structured` |
| 位置字段 | source_id + sheet 名 + 表头行区间 + 数据行号 |
| 输出 | 每区域一个 Table Element：多行表头合并展开 + 行记录；隐藏行列带标记保留 |
| 失败状态 | 区域识别失败→该 sheet PENDING_REVIEW，不整文件失败 |
| 质量检查 | 单元格守恒（输出=非空输入，合并展开计入）；表头存在性；隐藏行列保留 |

## R9 不支持格式

扩展名 ∉ {pdf,doc,docx,xlsx}：只登记不解析（zip 维持"暂不展开"决策）；`~$` 锁文件直接过滤。禁止入索引。

## 路由通用约束

1. 所有 Element 必带：source_id、extraction_mode、位置字段、解析器版本、**路由判定及触发原因**（P01-005 质量报告输入）；
2. "成功但可疑"（文本量骤降/cjk 异常/结构为空）→ PENDING_REVIEW，**宁挂起不放行**；
3. OCR 与文本混排文件（R2/R3）在 Element 级保留页 mode，检索侧可按 extraction_mode 加权或降权。
