# 问题学习卡：Q-040

> 本卡由 GLM 代写（2026-09-03 用户要求），复盘按代写卡处理。

## 问题

会议建议的CPU 4核方案是否落实到了总体设计方案的器件选型？两处资料能否闭环判定？

## 我认为这个问题要找什么

三段证据：①会议建议句（改谁：预处理模块；从 2 核改 4 核）；②Z0 总体设计方案的器件表（预处理模块那行的 CPU 备注）；③任何晚于会议日期、且覆盖预处理模块的选型资料。闭环 = ③存在且写明 4 核。

## 相关资料

- 文档类型：docx（会议纪要 + 方案设计 ×2）
- 资料之间的关系：纪要(03-06) → Z0 总体方案(03-05，早于会议) → Z1 方案设计报告(2025-06-13，晚于会议但范围不含预处理模块)
- 证据位置：纪要第（9）条；Z0 表1/表2 器件表；Z1 元器件选型表

## 资料中明确写了什么

【原文明确】纪要：建议预处理模块 CPU 由 2 核换 4 核。
【原文明确】Z0：两张器件表，CPU 均 FT2000-4，备注分别为"工业级4核版"（含 GPU 的表）和"工业级2核版"（含 FPGA V7 的表）。
【原文明确】Z1：单张器件表，CPU FT2000-4"工业级4核版"，文档范围仅 X100 计算模块+电源模块。
【推测，非原文】"4核版表=智能计算模块、2核版表=预处理模块"——按表内伴随器件推断，资料未写明表与模块的对应。

## 我不理解的术语

- 术语：预处理模块（Z0 语境的硬件模块）
- 出现位置：Z0 3.4 节、纪要第（9）条
- 我的暂时理解：Z0 平台架构中独立于智能计算模块的一个处理模块
- 是否需要确认：是（正样阶段是否保留该模块）

## 这个问题为什么有价值

它是"建议→设计闭环"的最小完整案例：一个建议、两个候选证据、一个陷阱（Z1 的 4 核不属建议对象）。考系统能否在同一关键词（4核）的多条命中里识别"对象不符"和"时间不符"的证据。

## 是否需要多个文件

- 是
- 纪要提供建议（对象+内容）；Z0 提供建议前基线；Z1 提供"看似落实实为无关"的干扰证据。三者缺一就答不对。

## 如果只做普通关键词检索，会遇到什么问题

- "CPU 4核"命中纪要建议句、Z0 表1、Z1 表6 三处，字面全部"支持已落实"，但逐一检查对象和时间后全部不成立；
- 器件表与模块的对应关系靠伴随器件推断，表内没写模块名；
- "未找到落实证据"和"找到未落实证据"是两个结论，检索无法区分。

## 这个问题需要什么检索能力

- 精确匹配：需要（定位三处证据）
- 语义匹配：需要（"换为4核"与"4核版"的字面不同）
- 表格检索：需要（器件表行）
- 元数据过滤：需要（文档日期：晚于 2024-03-06；范围：含预处理模块）
- 多文档组合：需要（三处证据联合推理）
- 图关系：是（建议→对象模块→该模块后续版本，正是一条两跳追踪路径）
- 时间关系：需要（会议日期 vs 文档落款）

## 答案边界

能答：建议内容、Z0 基线（2核）、Z1 不覆盖预处理模块。
不能答：是否落实——**正确答案就是"不能判定"**：无晚于会议且覆盖预处理模块的选型资料。把"找不到"答成"未落实"（有罪推定）或"已落实"（被 Z1 干扰）都是错。

## 我得到的航天资料知识

选型建议的闭环要跨"会议→方案版本"验证，且要防同名参数张冠李戴——同一颗 CPU 型号出现在多个模块，关键词相同、对象不同。

## 我得到的 RAG 技术知识

证据的时间有效性和对象一致性是检索之外的两个硬校验层；"证据不足"必须成为可输出的显式结论，这要求系统知道自己没找到什么，而不只是找到了什么。

## 由此形成的设计假设

- 假设：检索结果须带（对象, 时间, 类型）三重校验后才能支撑"落实"结论；校验不过 → 输出"证据不足"而非选次优答案。
- 验证方法：Q-040 作为 P02/P03 的拒答+校验测试题，统计"误判已落实"率。

## 仍然不确定的问题

- Z0 两张器件表与模块的对应关系（推测未验证）；
- 正样产品是否保留预处理模块（库内无证据，可能需用户提供背景）。
