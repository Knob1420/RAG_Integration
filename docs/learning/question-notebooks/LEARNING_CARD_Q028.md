# 问题学习卡：Q-028

> 本卡由 GLM 代写（2026-09-03 用户要求），复盘按代写卡处理。

## 问题

程控时间表8.31与9.2相比，程控安排发生了哪些变化？

## 我认为这个问题要找什么

两个 xlsx 的"Sheet2"（正式程控表：序号/北京时间/星上时间/任务/指令/判据 六列）逐行对比，找出条目的新增、删除和变更。不是看 Sheet1（8 月初的旧表）。

## 相关资料

- 文档类型：xlsx ×2（同系列文件的相邻版本）
- 资料之间的关系：同一模板的版本迭代（8.28→8.31→9.1→9.2），每版微调程控条目
- 证据位置：`程控时间表8.31.xlsx` Sheet2 与 `程控时间表9.2.xlsx` Sheet2（标题行下的条目区）

## 资料中明确写了什么

8.31 版：条目从"北京时间 2025-08-31 10:xx"起排，任务列出现"AI-9 GPU1 / GPU1-2"，指令码 `1020C0000073FF`，判据列引用 `TMU114`。
9.2 版：条目从"北京时间 2025-09-02 09:xx"起排，同模板同任务同指令码，条目数不同（9.2 的 Sheet2 为 10 行，8.31 为 9 行）。
（具体逐行差异需人工比对两表条目区——本卡未完成逐行 diff。）

## 我不理解的术语

- 术语：AI-9 / TMU114 / 星上时间与北京时间的偏差
- 出现位置：Sheet2 任务列、判据列、时间列
- 我的暂时理解：AI-9 是某轨道/任务代号；TMU114 是遥测代号（剩余可用程控指令数的判据）；星上时间与北京时间有固定偏差
- 是否需要确认：是（AI-9 含义、两表条目的精确 diff）

## 这个问题为什么有价值

程控表是"上星执行清单"——每版变化就是一次任务调整。回答它等于还原"这两天星上要做什么、改了什么"，是运维和追溯的刚需场景，也是检验系统做增量比对能力的最小案例。

## 是否需要多个文件

- 是
- 两个文件分别提供：旧版基线（8.31）与新版状态（9.2）；manifest 提供两文件的 mtime 排序线索。

## 如果只做普通关键词检索，会遇到什么问题

- 两表 90% 内容相同（同任务名、同指令码、同判据），关键词检索会命中两份几乎一样的证据，无法指出"变了什么"；
- 差异在行级（时间点、条目数），整篇相似度极高，语义检索也分不开；
- 需要先按版本过滤再逐行 diff，检索本身不解决问题。

## 这个问题需要什么检索能力

- 精确匹配：需要（版本定位：文件名+sheet 名）
- 语义匹配：不需要
- 表格检索：需要（行级条目）
- 元数据过滤：需要（版本/日期过滤二选一）
- 多文档组合：需要（两版并排比对）
- 图关系：可能（版本链 8.28→8.31→9.1→9.2 建边后，diff 沿边进行）
- 时间关系：需要（北京时间/星上时间双轨列）

## 答案边界

能答：两版的条目差异（需先完成逐行 diff）、模板结构、共同判据。
不能答：为什么调整（资料里没有变更说明）、星上时间偏差的成因、"8.28/9.1 两版"的内容（本卡未读）。

## 我得到的航天资料知识

程控任务以"北京时间+星上时间"双轨排程，每条含任务代号、指令码和遥测判据；时间表按日期滚动出新版，版本演进本身就是任务演化史。

## 我得到的 RAG 技术知识

近重复文档间的"差异"问题，检索（关键词/语义）都无法直接回答——它需要"版本对齐+结构化 diff"这一独立能力；高相似度反而会淹没真正的一两行差异。

## 由此形成的设计假设

- 假设：同模板系列文件按 content_sha256 聚成版本链，diff 在链上相邻两版之间做行级比较，输出结构化变更清单，而不是让模型读两份全文"找不同"。
- 验证方法：以 Q-028 为例，比较"行级 diff 输出喂给模型"与"两表全文喂给模型"的答案准确率与 token 消耗。
