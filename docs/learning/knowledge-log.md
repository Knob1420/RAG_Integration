## 2026-09-01 · 表内版本字段 ≠ 文件时间（源自 Q-006）

我原来以为：
文件修改时间就是资料的版本时间。

资料实际显示：
遥测汇总表各 sheet 自带"最后修订时间"字段（CPU遥控 20240828、CPU遥测 20240923），与文件 mtime 是两个独立时间；解压不恢复 rar 时间戳时 mtime 甚至全是解压当天。

技术上的含义：
版本类问题必须路由到表内字段；mtime 只能当排序线索。字段名必须区分 filesystem_mtime / document_version / effective_version，混用会产生系统性错答。

形成的假设：
把 sheet 表头字段提升为 chunk metadata 后，此类问题无需语义检索即可精确命中。

如何验证：
P02 基线上跑 Q-006，对比"有/无 sheet 级 metadata"两配置的命中率。

验证结果：
（待 P02）

对路线的影响：
P01 解析必须保留 sheet 级结构元数据；manifest 三版本字段分离已落地（P00-003A）。

## 2026-09-01 · 测试证据是 8 列一行的链（源自 Q-014）

我原来以为：
测试结论就是文档里一句"测试通过"。

资料实际显示：
老炼测试每项是 8 列表的一行：步骤→遥测判据→结果→结论在同一行，且同一遍历测了多轮（8/28、9/2），另有一份 0813 记录也有遍历——"通过"属于哪一轮哪一行，必须靠结构区分。

技术上的含义：
固定 token 切分会把"判据"和"结论"切进不同 chunk；检索命中的"通过"可能属于错误轮次。表格要按行组（测试项）切并保留轮次上下文。

形成的假设：
测试类文档按测试项行组切分，证据完整性优于固定 token 切分。

如何验证：
Q-014/Q-011 在两种切分下比较证据完整性（条件、结果、结论三者同召率）。

验证结果：
（待 P01/P02）

对路线的影响：
P01 切分策略必须类型化（至少区分长文/表格/短纪要三类），见 P00-data-profile 五策略。

## 2026-09-01 · "建议落实了吗"的正确答案常常是"判不了"（源自 Q-021/Q-040）

我原来以为：
会议建议 4 核，后文出现"4核版"，说明已落实。

资料实际显示：
方案落款（03-05）早于会议（03-06）；后出的 Z1 报告范围不含预处理模块，其"4核版"属于智能计算模块自己的 CPU——三处字面证据全部"支持落实"，逐一核对对象和时间后全部不成立。

技术上的含义：
证据要通过（对象、时间、类型）三重校验才能支撑因果结论；"找不到落实证据"≠"未落实"。系统必须能输出"证据不足"。

形成的假设：
检索结果带三重校验层，校验不过→显式拒答，不选次优答案。

如何验证：
Q-040 作为拒答组测试题，统计"误判已落实"率。

验证结果：
（待 P02/P03）

对路线的影响：
P03 评测集必须包含拒答类指标；P05 追溯图的"建议→设计"边只能标候选，无闭环证据不得定为确认边。

## 2026-09-01 · 近重复版本间的问题检索解决不了（源自 Q-028）

我原来以为：
两份程控时间表的差异，把两份都检索出来让模型比较即可。

资料实际显示：
两表 90% 内容相同（同任务名、同指令码、同判据），差异在行级时间点和条目数——整篇高相似度会淹没真正的一两行差异。

技术上的含义：
"找不同"是 检索之外的独立能力：版本对齐 + 结构化 diff。语义相似度在此类问题上天然失效。

形成的假设：
同模板系列按 content_sha256 聚成版本链，diff 在链上相邻版本间做行级比较，输出结构化变更清单。

如何验证：
Q-028 上比较"行级 diff 喂模型"与"两表全文喂模型"的准确率与 token 消耗。

验证结果：
（待 P04/P05）

对路线的影响：
P01 主副本判定（已定口径）是前置；diff 能力排期在 P04/P05，不进 P02 基线。

## 2026-09-01 · 拒答的前提是知道"证据读不了"（源自 Q-037）

我原来以为：
检索不到结果，系统自然不会回答。

资料实际显示：
三份验收测试记录表是无文本层扫描件——检索为空，但别处文件有"验收测试…通过"句子，系统很可能拿错证据顶替回答，看起来合理。

技术上的含义：
必须区分三种状态：证据不存在 / 存在但未解析（PENDING）/ 已解析未命中。只有第三种允许答"资料中没有"。parse_status 必须参与检索路由。

形成的假设：
检索前按 parse_status 分流，未解析 source 进入"不可用证据清单"随答案返回。

如何验证：
Q-020/Q-037 拒答组测试，检查是否输出"扫描件未解析"而非借用他文结论。

验证结果：
（待 P02；OCR 化后在 P01 重测）

对路线的影响：
P01 解析管线必须维护 parse_status 流转；扫描件 OCR 决策（暂缓）直接影响拒答组得分。
